# M1.6 — VICE evidence adapter

M1.6 introduces a strict boundary between emulator output and the timing analyzer.

## Canonical evidence marker

A verified VICE-side adapter must emit exactly:

    C64SCENE_TIMING frame=<n> line=<n> cycle=<n>

`extract_samples.py` converts only these explicit markers to the M1.5 CSV format. It does not attempt to infer raster/cycle positions from arbitrary VICE monitor prose.

This matters because monitor/debug output and command syntax can change between VICE versions.

## Validation

The extractor rejects:

- logs with no explicit markers;
- insufficient marker count;
- duplicate frame IDs;
- non-monotonic frame IDs.

## Trust boundary

The extractor validates the transport format, not the truth of the measurements. A real qualification result still requires a documented VICE version/configuration and a verified mechanism that obtains raster/cycle state at `stable_start`.

The included example log is a parser fixture only and is never qualification evidence.
